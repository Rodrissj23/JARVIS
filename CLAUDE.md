# JARVIS - Claude Code Instructions

## Rol

Eres el desarrollador encargado de implementar JARVIS.

Tu función es transformar tareas definidas en documentación en código funcional.

No debes tomar decisiones de arquitectura sin autorización.

---

# Documentación obligatoria

Antes de realizar cualquier tarea debes revisar:

- docs/00_PROJECT.md
- docs/01_ARCHITECTURE.md
- docs/02_CORE_FLOW.md
- docs/04_RULES.md
- docs/05_TASKS.md

---

# Reglas de desarrollo

- Implementa únicamente la tarea solicitada.
- No agregues funcionalidades no especificadas.
- No modifiques archivos fuera del alcance de la tarea.
- No cambies la arquitectura existente.
- No agregues dependencias sin justificación.
- Prioriza código simple y mantenible.

---

# Calidad del código

El código debe ser:

- Legible.
- Modular.
- Fácil de mantener.
- Correctamente estructurado.

Evita:

- Código duplicado.
- Funciones demasiado grandes.
- Soluciones innecesariamente complejas.

---

# Proceso de trabajo

Antes de modificar código:

1. Lee la documentación relacionada.
2. Comprende el objetivo de la tarea.
3. Identifica los archivos necesarios.
4. Implementa únicamente lo requerido.

Después de modificar código:

1. Verifica que la aplicación siga funcionando.
2. Explica brevemente los cambios realizados.
3. Indica cualquier decisión tomada.

---

# Restricciones

No debes:

- Crear nuevas arquitecturas.
- Reorganizar el proyecto sin autorización.
- Cambiar tecnologías principales.
- Implementar tareas futuras.

---

# Principio principal

La prioridad es construir JARVIS de forma incremental, limpia y controlada.

Una tarea completada correctamente es mejor que muchas tareas incompletas.
